Divergences found between the two builds

  • sha256/sha512: sync in node (crypto.createHash), async in browser (subtle.digest). A caller that forgets await works only in node. That breaks the "consumer notices no difference" goal.
  • Browser uses window.crypto, so it breaks in workers and Deno.
  • Both carry the keyBytes.buffer offset bug and the for b in saltContent bug from the handoff.

What the platforms give us now

  • globalThis.crypto.subtle exists in Node ≥19, Deno, Bun, browsers and workers, with the same API everywhere.
  • Uint8Array.prototype.toHex / Uint8Array.fromHex are native (Node 25+, verified on our node 26; Chrome 140, Firefox 133, Safari 18.2).
  • @noble/ed25519 is at 3.x (we pin 2.x). v3 renames ExtendedPoint→Point and randomPrivateKey→randomSecretKey.
  • 0.x semver: ^0.3.1 never resolves to 0.4.0. Every consumer bumps deliberately, so it's a good moment for breaking changes.

Risks worth naming

Async sha (D2): any node consumer calling sha256() without await gets a Promise. Grep the 23 ^0.3 consumers before release.
Legacy fixtures must be generated with the published 0.3.1 before we touch code, or we lose the ground truth.
Node ≥20 floor (WebCrypto global + native hex in 25+, inline fallback below). Older services would need an upgrade.
